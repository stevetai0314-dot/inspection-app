# 織帶巡檢異常回報系統

**Live:** https://stevetai0314-dot.github.io/inspection-app/

---

## 設計理念

這套系統的核心邏輯只有一句話：**走過去沒問題，就不登記。**

傳統 Google 表單要求巡檢員對每一台機器從頭到尾勾選「合格 / 不合格」，但工廠實務是：巡檢員走一條路線，碰到正常的機台根本不會停下來。強迫填寫正常結果只是增加摩擦、拖慢速度。

因此本系統改採「**只記異常**」邏輯——

- 沒問題的機台 → 直接走過，什麼都不用填
- 有問題才停下來 → 輸入機台號，點選異常類型，填具體數值，送出

表單平均填寫時間目標：**30 秒內完成一筆異常回報**。

## 功能架構

### 前端
- 單一 HTML 檔案，無框架依賴，可直接部署到 GitHub Pages
- 響應式 Mobile-first 設計，以手機操作為主
- 中越雙語一鍵切換（不雙語並存），語言設定存入 localStorage

### 後端
- Google Apps Script (GAS) 接收 POST 請求，寫入 Google Sheets
- 前端以 `fetch + mode:no-cors` 送出 JSON，不需要後端 CORS 設定

### 資料流
```
巡檢員手機 → HTML 表單 → GAS Endpoint → Google Sheets
```

## UX 決策說明

### 1. 異常項目固定在頂端（sticky）
點選「帶寬 / 勾高 / 電熱 / 外觀」後，對應的填寫卡片會展開在下方。但如果巡檢員想繼續新增第二個異常，不應該要求他滑回頂端。因此新增按鈕列採用 `position: sticky`，跟著螢幕移動，隨時可點。

### 2. 語言切換是全面替換，不是雙語並存
台灣幹部用中文，越南員工用越文。同一支 app、兩種語言，但每次只顯示其中一種。切換按鈕在右上角，點「中」或「VI」即可，設定存入 localStorage 不會重置。

實作方式：所有文字節點用 `data-zh` / `data-vi` 屬性儲存雙語版本，`applyLang()` 函式統一切換，不在 DOM 留下任何雙語痕跡。

### 3. 機台號大字輸入
機台號是這張表最重要的欄位，特意做成 36px 粗體置中，手指操作時不容易打錯也方便核對。

### 4. 外觀缺陷用 Code + 名稱雙欄 chip
外觀缺陷共 25 種（D、Y、S、H、W、M 系列），對老員工來說 code 已經是慣用語言，對新員工來說有中越文說明。選中後 chip 變紅，一眼看出已勾選哪些。

## 巡檢項目對應

| 類型 | 欄位 | 備註 |
|------|------|------|
| 帶寬 (Độ rộng) | 左 / 右 偏差值 | 格式如 `-1 / +2` |
| 勾高 (Cao móc) | 左/右 × 邊界側/中間/針側 | 共 6 格數值 |
| 電熱 (Nhiệt) | 左/右 × 邊界側/中間/針側 | 共 6 格數值 |
| 外觀 (Ngoại quan) | 左/右各選缺陷 chip | 25 種缺陷代碼 + 其他 |

---

## 表單欄位對應 Google Sheets

| 欄位 | 說明 |
|------|------|
| timestamp | 送出時間（台灣時區） |
| inspector | 巡檢人員姓名 |
| so_may | 機台號 |
| do_rong_trai / phai | 帶寬左/右 |
| cao_trai / phai | 勾高左/右（三點值） |
| nhiet_trai / phai | 電熱左/右（三點值） |
| ngoai_quan_trai / phai | 外觀左/右（缺陷代碼清單） |

未開啟的異常類型欄位送出空字串，Sheets 端可依此判斷是否有異常。
