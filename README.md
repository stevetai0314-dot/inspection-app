# 織帶巡檢異常回報系統

**Live:** https://stevetai0314-dot.github.io/inspection-app/

---

## 設計理念

這套系統的核心邏輯只有一句話：**走過去沒問題，就不登記。**

巡檢員在生產現場手抄數據，回到辦公室後用電腦集中輸入。系統以「**只記異常**」為原則——

- 沒問題的機台 → 空白跳過，不需要任何操作
- 有問題才填 → 輸入機台號、填異常數值、送出

設計目標：**從輸入機台號到送出，全程不需要碰滑鼠。**

---

## 操作流程

```
開啟網頁
   ↓
輸入機台號（Enter 確認）
   ↓
填寫異常項目（Tab 略過無問題的類別，Enter 跳下一格）
   ↓
送出（Enter）
   ↓
自動回到機台號輸入，等待下一筆
```

### 鍵盤快捷鍵

| 位置 | 按鍵 | 動作 |
|------|------|------|
| 機台號輸入 | `Enter` | 進入表單 |
| 類別標題（帶寬 / 勾高 / 電熱 / 外觀） | `Tab` | 略過此類別，跳到下一個 |
| 類別標題 | `Enter` / `Space` | 進入此類別第一個輸入格 |
| 輸入格內 | `Enter` | 跳到下一格 |
| 輸入格內 | `Tab` | 同上 |
| 送出按鈕 | `Enter` | 送出 |
| 成功畫面「下一台」 | `Enter` | 回到機台號輸入 |

---

## 空白 = 沒問題

所有欄位預設空白。送出時只有**有填值的類別**才會寫入 Google Sheets，空白欄位送出空字串，代表該類型本次無異常。

## 功能架構

### 前端
- 單一 HTML 檔案，無框架依賴，部署於 GitHub Pages
- 桌機優先設計，以鍵盤操作為主
- 中越雙語一鍵切換，設定存入 localStorage

### 表單結構
- **機台號輸入頁**：大字輸入框，鍵入機台號後 Enter 進入表單。若該機台昨日有異常回報，輸入時即顯示提示。
- **表單頁**：四個類別永遠展開，無需點擊卡片。昨日異常數值顯示於頁首供對比。

### 後端
- Google Apps Script (GAS) 接收 POST 請求，寫入 Google Sheets
- 提供 GET 介面回傳昨日各機台異常資料（JSONP 繞過 CORS 限制）

### 離線佇列
- 送出時先存入 `localStorage` 佇列
- 有網路時立即上傳，成功後刪除本機那筆
- 無網路時顯示「已暫存本機」，連線後自動補傳（`online` 事件觸發）
- Header 右上角顯示待傳筆數，可手動點選立即上傳

## 巡檢項目

| 類型 | 欄位 | 說明 |
|------|------|------|
| 帶寬 (Độ rộng) | 左 / 右 | 偏差值，如 `-1`、`+2` |
| 勾高 (Cao móc) | 左/右 × 邊界側/中間/針側 | 共 6 格，小數點數值 |
| 電熱 (Nhiệt) | 左/右 × 邊界側/中間/針側 | 共 6 格，整數溫度 |
| 外觀 (Ngoại quan) | 左/右各選缺陷 chip | 25 種缺陷代碼（D / Y / S / H / W / M 系列）+ 其他 |

## UX 決策記錄

### 1. 直接輸入機台號，不選區域
生產現場巡檢後回辦公室輸入，已知機台號，不需要從區域清單尋找。直接輸入比三層點選快。

### 2. 空白 = 無異常，不用主動略過
電腦操作者用 Tab 快速跳過沒問題的類別，空白欄位不送出有效值。主管端以空字串判斷本次無該類型異常。

### 3. 送出後自動循環
一個班次可能有多台機台需要回報，送出後自動回到機台號輸入，不需要手動重置或點選返回。

### 4. Tab 跳類別，Enter 跳欄位
Tab 在類別標題層級跳動（可略過整個類別），Enter 在欄位層級跳動。兩層導航讓鍵盤操作不需要碰滑鼠。

### 5. 雙語切換不雙語並存
台灣幹部用中文，越南員工用越文。所有文字用 `data-zh` / `data-vi` 屬性儲存，`applyLang()` 統一切換。

### 6. 昨日異常即時提示
輸入機台號時即檢查昨日資料，有異常立即顯示。進入表單後頁首也顯示昨日具體數值，方便與今日測量值對比。
